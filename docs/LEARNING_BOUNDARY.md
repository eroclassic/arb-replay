# Learning boundary

ArbReplay is a learning project. The following work should be designed,
implemented, and explained by the project owner:

- fixed-point price, money, and quantity types;
- order-book representation and reconstruction;
- implied YES/NO ask calculations;
- complement and basket arbitrage conditions;
- payoff and profit calculations;
- deterministic replay ordering and clock handling;
- fee, depth, latency, and partial-fill models;
- important unit tests and benchmark interpretation.

AI assistance is appropriate for build configuration, CI, parsing boilerplate,
compiler-error explanations, code review, edge-case suggestions, documentation,
and optional research charts. Core-path code should only be generated when the
owner explicitly asks for it after attempting the implementation.
